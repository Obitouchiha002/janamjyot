1 Project Overview

VedicAstra is a full-featured Vedic astrology web application. It generates a person’s birth chart entirely from a built-in astronomy engine (no paid chart API required), and layers an AI guidance system on top that interprets the chart in a warm, human, and specific way.

The product is built so a single operator only needs to paste API keys — everything else (chart calculation, divisional charts, dashas, transits, matching, panchang, remedies and AI chat) works out of the box.

4 The Astrology Engine (Original & Accurate)

Instead of depending on a paid chart API, VedicAstra computes everything itself using the pure-JS astronomy-engine (Swiss-Ephemeris-grade) and the classical Lahiri ayanamsa.

What it computes

  • True-of-date geocentric ecliptic longitudes for all 9 grahas + Ascendant
  • Sidereal positions via Lahiri ayanamsa (23.8523° + 50.2388″/yr from J2000)
  • Whole-sign houses, nakshatra + pada, retrograde detection
  • Divisional charts (D1, D9, D10, D6, D11 …) using BPHS & parivritti rules
  • Vimshottari Mahadasha / Antardasha timeline
  • Live transits (gochar), Ashtakavarga bindus, Panchang elements, RA/Declination/Shara

Validated

For the reference Alwar chart, every planet and the Ascendant match AstroSage & Prokerala within ~0.01°, and the Vimshottari dasha dates match too.

6 The Multi-AI Engine (never runs out)

The biggest early pain was the AI quota dying in a single message. The fix: a layered fallback chain that auto-switches the instant a provider hits its limit.

  • 12 independent Gemini buckets (3 keys × flash/flash-lite models) — each has its own daily free quota.
  • Groq (fast, free) → Bedrock/Claude (paid) → Ollama local model as the final, limitless safety net.
  • On any 429/quota error the next provider is tried automatically — chat never fully stops.
  • Admin can toggle each AI feature off for cost control.

Voice

“Listen” uses ElevenLabs’ fast multilingual model (turbo, streamed); if credits/keys are unavailable it silently falls back to the browser’s free voice.

8 Step-by-Step Build Journey

Phase 1 — Foundation. Set up the Vite + React + Express stack; integrated birth-detail input with place autocomplete (no need to know latitude/longitude/timezone).
Phase 2 — Real charts. Started with the Prokerala API, then built our own astronomy engine to remove the dependency and guarantee accuracy.
Phase 3 — Interpretation. Added the AI layer (“Acharya” persona), normalized chart data, and the multi-provider fallback so quota never dies.
Phase 4 — Depth. Divisional charts, dashas, live transit (animated wheel), Ask-AI 4-phase answers, Life Sectors, and a polished PDF Life Report.
Phase 5 — Advanced tools. Kundli Matching, Daily Panchang + horoscope, Muhurat finder, Yoga detection, Ashtakavarga, Remedies, “Aaj Ka Din”.
Phase 6 — Experience. 5 themes + dark mode, voice output (ElevenLabs), help & support with direct email, multi-language answers.
Phase 7 — Platform. Accounts + login, per-user data isolation, and a full admin dashboard for launch.

9 Problems Faced & How They Were Solved

1 · “Chart galat ban raha hai”

Charts were occasionally wrong.

Root cause & fix

Two issues: (a) the Prokerala API rate-limited at 5 calls/60s causing intermittent failures, and (b) an AM/PM time-entry bug (6:40 AM stored as 11:40). Fixed with retry/back-off, then by replacing the API with our own engine, and a clear 12-hour time picker.

2 · Sanskrit sign names broke houses

Signs like “Tula” weren’t recognised, so houses computed wrong.

Fix

A sign-alias map (Tula→Libra, Mesha→Aries …) normalizes every spelling to a canonical index; houses are derived from the Ascendant, not the raw provider field.

3 · AI quota died in one message

The top model had a tiny free quota.

Fix

Flash-first ordering + 3 keys × 4 models = 12 independent daily buckets, then Groq → Bedrock → local Ollama. Practically impossible to exhaust in a day.

4 · Microphone “not secure”

Voice input needs HTTPS.

Fix

Added a self-signed HTTPS server alongside HTTP for local use (2048-bit, SHA-256), so the mic works on localhost and LAN.

5 · Premium AI/voice limits & billing

The Claude key was an AWS Bedrock key (payment-gated), and ElevenLabs was slow.

Fix

Auto-detected Bedrock keys and routed correctly; made Ollama the limitless local fallback; switched TTS to the streamed turbo model for speed.

9 Problems & Solutions (continued)

6 · Missing Ascendant index

Yogas, Ashtakavarga & Remedies used the wrong Lagna reference.

Fix

Derived the Ascendant sign index from its name everywhere, restoring correct Lagna-lord, yoga and bindu calculations.

7 · Muhurat showed every day

Marriage muhurat appeared even in months when weddings don’t occur.

Fix

Added the real seasonal rules — Kharmas, Chaturmas, Guru/Shukra Ast (combustion), Vivah-nakshatra & tithi checks. Cross-checked against published panchang (Aug/Sep/Oct correctly empty; Nov dates matched).

8 · “Aaj Ka Din” regenerated on every refresh

Wasted AI quota.

Fix

The daily snapshot is generated once per day per user and cached; every refresh returns the same report.

9 · Messy PDF

The Life Report PDF felt cramped and plain.

Fix

Redesigned with a clean header, birth details, D1/D9 charts, dasha tables, bold highlights, an end summary, and lazy-loaded jsPDF (smaller app bundle).

11 Security & Privacy

  • All secrets server-side — Prokerala, Gemini, Groq, Bedrock, ElevenLabs, SMTP keys never reach the browser.
  • Hashed passwords (scrypt) and signed JWT sessions; suspended accounts are blocked.
  • Per-user data isolation — a user can only access their own charts (ownership enforced on every route).
  • Admin-only controls — stats, user management and feature flags require the admin role.
  • Private by design — data is stored locally to the deployment; nothing is shared with third parties beyond the AI calls the user initiates.

Before public launch

Set a strong AUTH_SECRET, lock CORS to the real domain, add rate-limiting + security headers, move to a persistent database, and publish Privacy / Terms / Disclaimer pages.

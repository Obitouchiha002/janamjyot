1 Purpose & Scope

This SOP defines the standard steps to install, run, operate, maintain and troubleshoot the VedicAstra platform. It is intended for the operator/admin and any developer maintaining the system.

System summary

  • One Node/Express server serves the React app and a secured /api.
  • All astrology is computed by a built-in engine; AI providers and voice are brokered server-side.
  • Accounts + login + a per-user data model, with an admin dashboard for control.

4 Running the App

Development

  1. Open a terminal in the project folder.
  2. Run npm run dev.
  3. Open http://localhost:3000. (For microphone/voice on other devices use https://localhost:3443 and accept the one-time warning.)

Important

The server does not auto-reload on backend (server.ts) changes. After editing backend code or .env.local, stop and restart npm run dev.

Production

  1. Set NODE_ENV=production and all secrets in the host’s environment.
  2. Build: npm run build.
  3. Start: npm start (serves the built app + API).

5 Daily Operations

  1. Confirm the site loads and login works.
  2. Open Admin → Overview: check new signups, charts created, totals.
  3. Open Admin → System & AI: verify at least one AI provider shows status “ok”; watch quota hits.
  4. If a paid provider is near its limit (ElevenLabs credits / Bedrock), consider turning that feature off in Controls.
  5. Respond to any Help messages received by email.

Healthy signs

AI status “ok” or “quota” with auto-recovery; chat & reports returning; no error spikes.

6 Admin Procedures

Manage a user

  1. Go to Admin → Users.
  2. Promote/demote admin (shield icon), Suspend/Unsuspend, or Delete (with confirm).
  3. Suspended users are immediately blocked from the app.

Pause the app (maintenance)

  1. Admin → Controls → App Status: type a message, click Pause App.
  2. Regular users see the message; admins keep full access. Click App Live to resume.

Announcement banner

  1. Controls → Announcement: type a message, click Show banner (appears for all signed-in users). Hide to remove.

Cost control (feature flags)

  1. Controls → Feature flags: toggle AI Chat / Reports / Voice / Horoscope / Match.
  2. Turned-off features fail gracefully (voice falls back to free browser voice).

7 API Keys & Quota Management

  • Gemini (free): each (key × model) pair has its own daily quota. The app already lists 3 keys × 4 flash models = 12 buckets. If chat slows, add another Google account’s key as GEMINI_API_KEY_3 and restart.
  • Ollama (local): if installed and set via OLLAMA_MODEL, it’s the limitless final fallback (offline, free, slower).
  • ElevenLabs (paid): watch credits; if exhausted, the app auto-uses the free browser voice — no breakage. Rotate the key in .env.local and restart.
  • Bedrock/Claude: requires a valid AWS payment method; if it returns a payment error, leave it as backup — the free providers serve normally.

Rotating any key

Update the value in .env.local (or host env) → restart the server. Keys are never exposed to the browser.

8 Troubleshooting (step-by-step)

SymptomAction
AI not replying / “quota” errorWait ~1 min (auto-fallback). Check Admin → System & AI. Add another Gemini key or enable Ollama. Restart server.
Chart looks wrongVerify date is YYYY-MM-DD, time AM/PM correct, and the right place was picked from suggestions. Recreate the chart.
Microphone “not secure”Open via http://localhost:3000 or https://localhost:3443 (accept warning). Mic needs a secure origin.
Voice (Listen) silent/slowCheck ELEVENLABS key/credits; otherwise it falls back to browser voice. Verify the feature flag is ON.
Help email not sendingSet SMTP_USER + a Gmail app password in SMTP_PASS; restart. Until then it opens the user’s email app.
Login fails / 401 loopEnsure AUTH_SECRET is stable (don’t change it in prod). Restart after changing env.
Backend change not taking effectRestart npm run dev — backend doesn’t hot-reload.
Users/charts disappeared after deployThe host’s filesystem is ephemeral — switch to Postgres or a persistent volume.

9 Backup & Data Safety

  • File store: data lives in .data/store.json. Back it up regularly (copy the file). It is auto-backed-up if it becomes corrupt.
  • Postgres: enable the provider’s automated daily backups.
  • Never commit .env.local or .data/ to git.

10 Deployment Procedure

  1. Choose a host (Railway/Render/VPS) with a persistent database or volume.
  2. Set all secrets in the host environment (incl. strong AUTH_SECRET).
  3. Build (npm run build) and start (npm start).
  4. Attach a domain; enable HTTPS (host/Let’s Encrypt).
  5. Lock CORS to the domain; add rate-limiting & security headers.
  6. Sign up the admin account; set announcement/flags; smoke-test the full flow.
9–10 · Backup & Deploy10

11 Security Do’s & Don’ts

Do

  • Keep all keys in env / host secrets only.
  • Use a strong, stable AUTH_SECRET in production.
  • Back up data before each deploy; rotate keys if leaked.
  • Use feature flags to cap paid AI/voice usage.

Don’t

  • Don’t commit .env.local or expose keys in the frontend.
  • Don’t leave CORS open in production.
  • Don’t rely on the file store on an ephemeral host.
  • Don’t change AUTH_SECRET in prod (logs everyone out).
